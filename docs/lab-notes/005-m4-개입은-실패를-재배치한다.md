# 005 — M4 결과: 개입은 실패를 없애지 않고 재배치한다

날짜: 2026-07-19 · 실험: m4-planner (72런, 유효 채점기) · 관련: [003](003-툴콜-유효율-null-result.md), [004](004-채점기-오염-대소문자와-동의-페이지.md)

## 상황

M4 재실행(수정된 채점기) 완료. control 88% / +planner 83% / +evidence 71%.
두 개입 모두 순효과 마이너스 — 그러나 태스크별로 보면 상쇄 구조다.

재실행 자체도 순탄치 않았다: 실험 프로세스가 스왑 압박(swap 5.9GB, 여유 70MB,
LLM 호출당 100~135초) 속에서 두 번 죽었고, `--resume` 기능(metrics.sqlite에
기록된 런을 복원해 건너뛰기)을 추가해 63런 지점부터 이어 완주했다. answer
컬럼을 저장해 둔 것(004의 교훈)이 재채점과 resume 모두를 가능하게 했다.

## 증거

태스크별 성공(3반복 중):

| task | control | +planner | +evidence |
|---|---|---|---|
| q-109 (시맨틱 vs LRU 캐시) | 0 | **3** | 1 |
| q-111 (GAS vs MCP 자동화) | 3 | **0** | 3 |
| q-107, q-108 | 3, 3 | 2, 3 | **1, 1** |

- control q-109 실패 답변: 검색 0회, 실존하지 않는 개념명 `[[LRU 캐시]]`,
  `[[시맨틱 캐시]]` 인용 — 전형적 탐색 소극성.
- planner q-111 실패 답변: 내용은 두 작업을 모두 정확히 다루는데 인용은
  `[[코멘토-gas-교육효과-대시보드]]` 하나뿐. temperature 0.2에서 3회 동일하게
  실패 — 노이즈가 아니라 결정적 행동.
- evidence 실패 답변들: 반려 후 read_page로 근거를 읽고 재답변하지만 한쪽
  그룹 인용을 누락. 반려는 24/24회 발동, 토큰 4.8배(1876→9058), 스텝 1.9→5.0.
- 채점 갭 2차 발견: q-101에서 세 설정 모두 `[[프로젝트-판옵티콘-모니터링]]`
  (허브)과 `[[oauth2-인증-플로우]]`(재사용 개념, "판옵티콘에서의 실제 코드"
  섹션 보유)를 인용했는데 그룹에 없어 오답 처리되고 있었다. 그룹 보정 후
  저장된 답변으로 재채점 — 재실행 없이 88/83/71%로 확정.

## 해석

1. **탐색 소극성 가설(003)은 부분 참**. 정확히 그 실패 모드를 가진 태스크
   (q-109)에서 planner 프롬프트는 0→3으로 완벽히 작동했다.
2. **개입의 숨은 비용은 형식 규율**. 8B 모델에서 시스템 프롬프트 지시가
   늘거나(planner) 컨텍스트가 길어지면(evidence 반려 후) 내용 정확성보다
   인용 형식이 먼저 무너진다. 개입이 실패를 "제거"한 게 아니라 다른 태스크로
   "재배치"했다.
3. **결정적 채점기는 실패 답변 검시가 필수**. 두 번의 채점 갭(004: 대소문자·
   동의 페이지, 005: 허브·재사용 개념 페이지) 모두 실패 답변을 직접 읽어야
   드러났다. 집계 숫자만 보면 틀린 결론을 확신하게 된다.

## 결정

- M4 유효 결론으로 확정, 리포트에 결론 병기
  (reports/ablation-m4-planner-2026-07-19.md).
- 상시 개입 대신 **조건부 개입**을 다음 가설로: 인용 0개이거나 실존하지 않는
  페이지명 인용일 때만 반려. q-109류만 잡고 q-111류 부작용을 회피.
- 반려 메시지에 인용 형식 재고지를 포함해 형식 규율 상실을 보상.

## 영향

- 러너에 `--resume` 상시 탑재 — 장기 실험이 죽어도 sqlite 기록 지점부터 재개.
- 태스크 page_groups 작성 규칙: 허브 페이지·재사용 개념 페이지도 해당 내용을
  실제로 담고 있으면 유효 근거로 포함할 것.
- 16GB에서 evidence류(툴콜 다발) 실험은 스왑 절벽 위험 — 임베더⇄생성기 왕복이
  잦은 설정은 런당 3~5배 느려질 수 있음을 실험 설계 시 반영.
